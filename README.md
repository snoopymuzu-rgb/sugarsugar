# Sugar Sugar 開發版

Web 會員端、管理後台，以及同層 `sugar-sugar-mobile` 的 Expo iOS／Android 原始碼。

## 已實作

- 伺服器驗證管理者名單；手機憑證不能進入管理 API。會員只取得自己的訂單，不取得平台營收。
- 成年聲明與人工審核、個人資料、雙向配對、訊息、活動及容量限制、檢舉／封鎖、資料匯出與刪除。
- 每次互動檢查審核狀態與伺服器時間；到期、停權或刪除後禁止讀寫互動。到期仍可續會及使用安全功能。
- 綠界信用卡單次付款訂單、SHA-256 通知檢核、伺服器定價、重複通知防護、30 天續期及本人訂單紀錄。停權／刪除帳號付款列為人工處理，不恢復帳號。
- 測試交易獨立標示，不計正式營收，不開通正式會員。SimulatePaid=1 不變更任何訂單或權限。
- 100 個明確標示 AI 的角色；實際對話預設關閉，需伺服器服務設定。

## 啟動與驗證

Node.js 24；`npm ci`、`npm run dev -- --host 127.0.0.1`。本機 D1 與正式 D1 分離。`.dev.vars` 是忽略檔，勿提交憑證。

`npm run db:generate` 產生新增遷移；既有遷移不得修改。使用 Wrangler 對 `--local --persist-to .wrangler/state` 套用 `drizzle/*.sql`。Sites 發布會套用正式遷移。

- `npx tsc --noEmit`
- `node --test tests/policy.test.mjs tests/billing.test.mjs`
- `node scripts/seed-test.mjs` 產生 **僅限本機** 測試資料，套用 `work/seed.sql` 後，以本機伺服器執行 `node --test tests/access.test.mjs`。
- `npm run build`

## 金流設定與啟用條件

目前付款預設關閉，尚未使用真實商家帳戶進行端到端付款。不要在對話、程式碼或 App 公開變數放入商家金鑰。

伺服器設定：`ECPAY_MODE=sandbox|live`、`ECPAY_MERCHANT_ID`、`ECPAY_HASH_KEY`、`ECPAY_HASH_IV`、`ECPAY_PUBLIC_ORIGIN`（精確 HTTPS 網站來源）、`ECPAY_PRICE_TWD`（確認過的整數新臺幣價格）、`ECPAY_CHECKOUT_ENABLED=true`。缺少有效設定會拒絕建立訂單。

付款通知位置為 `/api/billing/ecpay/notify`，必須可讓綠界無需網站登入直接存取。**目前私人 Sites 入口不符合此條件，不能啟用正式收款。** 需先安排公開正式服務／通知入口、確認商家申請與服務品項核准、完成測試交易、通知重送及人工對帳流程後才啟用。瀏覽器返回頁不是付款成功依據。

參考：[綠界檢查碼](https://developers.ecpay.com.tw/2902/)、[測試介接](https://developers.ecpay.com.tw/2856/)。本版不自動扣款，不提供退款操作或定期扣款；退款、爭議及未收到通知的對帳仍待完成。

## 尚未完成的正式上線工作

- 原生 App 的 Apple／Google 商店內購、收據驗證、商店通知及簽章／上架。Expo 匯出資源不是 APK／IPA。
- 可供手機連線的正式 API 與真機驗證；不得把 Sites 私人入口服務憑證放進手機。
- 身分／成年驗證供應商、影像上傳與審核、推播、內容安全營運、法律文件及營運資料。現有成年檢核屬自我聲明與人工審核，不能宣稱已完成第三方驗證。
- 付款退款對帳、管理者人工處理佇列（AI 安全事件目前只列在操作紀錄，尚無專屬處理佇列與通知）。
- AI 危機字詞清單需由營運與專業人員覆核；求助專線資訊上線前需再確認。
- 套件掃描仍有上游建置工具依賴告警，詳見開發紀錄；不可宣稱零漏洞或已達正式營運標準。

私人預覽僅供驗收，不應匯入真實身分證件、支付卡資料或其他敏感會員內容。

## 2026-10-07 更新

管理後台新增訂單收款分頁，提供正式／測試環境、付款狀態及訂單／會員／金流編號精確查詢，每頁 50 筆。正式收款總額包含待人工處理款，不含測試款；它是未扣除手續費或退款的原額。待處理款仍需人工核對，本版未自動退款或補發。

續會送出已確認價格；價格與伺服器或舊訂單不符時，拒絕建立付款表單，請使用者重新確認。

驗證涵蓋相同時間訂單分頁不漏列／重複、正式及測試款隔離、查詢參數處理、價格變更確認與未授權 API 存取。瀏覽器自動檢視工具受本機權限問題影響，視覺驗收尚未完成。

## 裝置管理更新

會員中心新增已授權手機清單，可撤銷單一或全部手機，包括已同意但未完成連接的授權。只回傳本人裝置、平台名稱、申請時間及期限，不回傳驗證密鑰或登入憑證。會員到期或停權後仍能管理裝置；撤銷不改變會員期限。裝置清單不包含瀏覽器登入。

手機收到登入失效回應後移除本機舊憑證，重新整理時切回未登入狀態。舊版裝置顯示一般名稱，不推測不存在的申請時間。iOS／Android 資源匯出成功，尚未完成真機驗證。

新增測試：node --test tests/devices.test.mjs。測試涵蓋本人裝置隔離、不得撤銷他人裝置、重複撤銷、未完成配對撤銷、配對單次使用及刪除帳號拒絕發證。付款流程新增停權後不得重用舊付款訂單的檢查。

## 2026-10-08 AI 安全檢查（Claude 接續開發）

AI 對話流程改為：輸入風險檢查 → 模型 → 輸出安全檢查 → 發送（PRD 4.4）。程式在 `lib/ai-safety.ts`，流程在 `lib/ai.ts`。

- 會員訊息含明顯輕生／自傷字句，或審核服務判定為自傷類別時：不送 AI、不扣額度、不保存內容，網頁與 App 顯示求助專線卡片（119／110、安心專線 1925、生命線 1995、張老師 1980），可直接點擊撥號。AI 未設定時一樣會顯示。
- 會員訊息被判定為兒少性內容、威脅、暴力或違法類別時：拒絕送出，不扣額度。
- AI 回覆被審核服務標記任何類別時：不顯示、不保存，額度退回，需重新送出。
- 審核服務故障時一律不送出（fail closed），不扣額度。
- 審核使用 OpenAI Moderation（`omni-moderation-latest`），沿用 `AI_API_KEY`，不需新增設定。
- 三種事件寫入 `audits`（`ai_support_shown`、`ai_input_blocked`、`ai_output_blocked`），只記錄會員、角色與時間，不保存對話文字；管理後台「操作紀錄」分頁以中文顯示。
- 不需要資料庫遷移。

新增測試：`node --test tests/ai-safety.test.mjs`（8 項）。原 `tests/ai.test.mjs` 已配合審核服務調整模擬回應，原有斷言不變。尚未以瀏覽器或真機做視覺驗收。
